# AI Films 产品架构设计

> 基于火山引擎全家桶（Seedream + Seedance + Doubao）构建自动化 AI 长视频生成产品
> 技术栈：TypeScript + CLI 先行，后续包装为 Web

---

## 1. 产品定位

**输入**：用户 ≤200 字故事描述 + 角色图片（1-3张）
**输出**：1-2 分钟完整 AI 影片（含叙事、连贯角色、无缝衔接）

---

## 2. API 配置

```typescript
// 统一代理网关
const VOLC_PROXY = "https://ai-apis.medomino.com/proxy/volcengine";

// API 端点（OpenAI 兼容格式，改 baseURL 即可）
const TEXT_API_URL  = `${VOLC_PROXY}/api/v3/chat/completions`;
const IMAGE_API_URL = `${VOLC_PROXY}/api/v3/images/generations`;
const VIDEO_API_URL = `${VOLC_PROXY}/api/v3/contents/generations/tasks`;

// 模型
const TEXT_MODEL  = "doubao-1-5-pro-32k-250115";     // LLM 编剧
const IMAGE_MODEL = "doubao-seedream-5-0-260128";     // 图片生成（替代 GPT Image 2）
const VIDEO_MODEL = "doubao-seedance-2-0-260128";     // 视频生成

// 统一认证
const API_KEY = process.env.VOLC_API_KEY; // 单 key 访问所有端点
```

### API 调用模式差异

| 能力 | 端点 | 模式 | 说明 |
|------|------|------|------|
| 文本生成 | `/chat/completions` | 同步 | 标准 OpenAI chat 格式 |
| 图片生成 | `/images/generations` | 同步 | 标准 OpenAI image 格式，返回 base64 |
| 视频生成 | `/contents/generations/tasks` | **异步** | 提交任务 → 轮询状态 → 获取结果 |

**视频生成异步模式**：
```
1. POST /contents/generations/tasks  → 返回 task_id
2. GET  /contents/generations/tasks/{task_id}  → 轮询直到 status=SUCCESS
3. 从 response 中获取视频 URL → 下载
```

└────────────────────────┬────────────────────────────────┘

│  Stage 1: 角色参考表 (Seedream)                          │
│                                                         │

                         ▼

│  Stage 2: 分镜板 (Seedream)                              │
│                                                         │
│  按幕生成，每幕 12 格 (4×3):                              │
│    60s → 2 页 (16 shots)                                │
│    120s → 4 页 (32 shots)                               │
│                                                         │
│  prompt = 分镜模板 + shots 描述 + character descriptions  │
│  output = storyboard/page-{N}.png                       │
│                                                         │
│  后处理:                                                 │
│    - 裁切每行 (4 格/行) → storyboard/row-{N}-{R}.png     │
│    - 放置到 16:9 黑底画布 → storyboard/canvas-{N}.png    │
│    - 检查重复面板 → 如有则重新生成该面板                   │
└────────────────────────┬────────────────────────────────┘
                         ▼
┌─────────────────────────────────────────────────────────┐
│  Stage 3: Prompt 组装                                    │
│                                                         │
│  遍历每个 15s 片段:                                      │
│    1. 选择模式 (模式A or 模式B)                           │
│    2. 选择衔接策略 (first_frame / occlusion / crossfade)  │
│    3. 组装完整 Seedance prompt (按 §3.2 最佳结构)         │
│    4. 写入 prompts/segment-{N}.json                      │
│                                                         │
│  每段 JSON:                                              │
│  {                                                       │
│    segment_id, mode, transition_strategy,                │
│    prompt_text, image_ref, reference_images,             │
│    duration, seed                                        │
│  }                                                       │
└────────────────────────┬────────────────────────────────┘
                         ▼
┌─────────────────────────────────────────────────────────┐
│  Stage 4: 视频生成 (Seedance 2.0)                        │
│                                                         │
│  对每段:                                                 │
│    1. 如需上传图片 → 转为可访问 URL                       │
│    2. POST /contents/generations/tasks (异步提交)         │
│    3. 轮询直到完成 (3-5 分钟/段)                          │
│    4. 下载视频 → clips/segment-{N}.mp4                   │
│    5. 提取末帧 → frames/segment-{N}-last.png             │
│                                                         │
│  串行模式: 段 N 完成后才提交段 N+1 (帧续接需要)           │
│  并行模式: 首段用模式B时，后续段可并行 (无帧依赖)          │

│    - 最多重试 3 次                                       │

│    - 用户可 ai-film regen --clip N 手动重试              │
└────────────────────────┬────────────────────────────────┘
                         ▼
┌─────────────────────────────────────────────────────────┐

│                                                         │
│  对每对相邻片段:                                         │
│    1. 检查衔接策略                                       │
│    2. first_frame_anchor:                               │
│         上段末帧 → 下段 image 参数                       │
│    3. occlusion_transition:                             │
│         验证遮挡帧效果                                   │
│    4. continuity_crossfade:                             │
│         标记 0.3-0.5s 淡入淡出                          │
│    5. hard_cut:                                         │
│         无需处理                                         │
└────────────────────────┬────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│  Stage 6: 合成 (FFmpeg)                                  │
│                                                         │
│  1. 统一分辨率/帧率 (1920x1080 @ 24fps)                  │
│  2. 按 transition 策略拼接:                              │
│     - crossfade: xfade filter                           │
│     - hard_cut: concat demuxer                          │

│  3. 输出 → output/final.mp4                              │

## 5. Provider 层设计

### volcengine.ts — 统一 API 封装

```typescript
import OpenAI from "openai";

// 文本和图片用 OpenAI SDK（兼容格式）
const client = new OpenAI({
  apiKey: process.env.VOLC_API_KEY,
  baseURL: "https://ai-apis.medomino.com/proxy/volcengine/api/v3",
});

// ─── 文本生成 ───
async function chat(messages: ChatMessage[], options?: ChatOptions): Promise<string> {
  const response = await client.chat.completions.create({
    model: "doubao-1-5-pro-32k-250115",
    messages,
    ...options,
  });
  return response.choices[0].message.content;
}

// ─── 图片生成 ───
async function generateImage(prompt: string, options?: ImageOptions): Promise<Buffer> {
  const response = await client.images.generate({
    model: "doubao-seedream-5-0-260128",
    prompt,
    size: options?.size ?? "1536x1024",
    n: 1,
    response_format: "b64_json",
  });
  return Buffer.from(response.data[0].b64_json, "base64");
}

// ─── 视频生成 (异步任务) ───
const VIDEO_BASE = "https://ai-apis.medomino.com/proxy/volcengine/api/v3";

async function submitVideoTask(params: VideoTaskParams): Promise<string> {
  // POST /contents/generations/tasks
  // 返回 task_id
  const response = await fetch(`${VIDEO_BASE}/contents/generations/tasks`, {
    method: "POST",
    headers: {
      "Authorization": `Bearer ${process.env.VOLC_API_KEY}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      model: "doubao-seedance-2-0-260128",
      ...params,
    }),
  });
  const data = await response.json();
  return data.id; // task_id
}

async function pollVideoTask(taskId: string, intervalMs = 10000): Promise<VideoResult> {
  // GET /contents/generations/tasks/{taskId}
  // 轮询直到 status !== "PROCESSING"
  while (true) {
    const response = await fetch(
      `${VIDEO_BASE}/contents/generations/tasks/${taskId}`,
      { headers: { "Authorization": `Bearer ${process.env.VOLC_API_KEY}` } }
    );
    const data = await response.json();

    if (data.status === "SUCCESS") {
      return { url: data.content.video_url, duration: data.content.duration };
    }
    if (data.status === "FAILED") {
      throw new Error(`Video task failed: ${data.error_message}`);
    }
    // PROCESSING — 继续轮询
    await sleep(intervalMs);
  }
}
```

## 6. Seedream vs GPT Image 2 适配

### 需要验证的差异点

| 能力 | GPT Image 2 | Seedream 5.0 | 适配方案 |
|------|-------------|--------------|---------|
| 多图输入 (edit) | 最多 16 张 | 待验证 | 如不支持，用纯文本描述 |
| 分镜板生成 | 支持 12 格网格 | 待验证 | 如效果差，分单格生成再拼合 |
| 角色参考表 | 支持 model sheet | 待验证 | 同上 |
| 任意分辨率 | 支持 (最高 4K) | 待验证 | 如不支持自定义，后处理 resize |
| input_fidelity | 支持 high | 不适用 | Seedream 无此参数，靠文本描述补偿 |
| 中文 prompt | 需英文 | 原生支持 | 可直接用中文描述角色 |

### 降级策略

```
IF Seedream 不支持多图输入:
  → 角色参考表用纯文本描述生成（不传参考图）
  → 分镜板用纯文本描述生成
  → 角色一致性依赖 Stage 3 中每段 prompt 重复详细描述

IF Seedream 分镜板质量不够:
  → 改为逐格生成（12 次 API 调用代替 1 次）
  → 后处理拼合为完整分镜板
  → 优点：每格可单独重试

IF Seedream 不支持自定义分辨率:
  → 生成后用 sharp resize 到目标尺寸
  → 分镜板裁切后放置到 16:9 画布
```

## 7. 项目状态管理

```typescript
interface ProjectState {
  projectId: string;
  createdAt: string;
  config: {
    story: string;
    duration: number;          // 60 | 90 | 120
    style: "cinematic" | "anime" | "3d-pixar";
    seed: number;
    resolution: "720p" | "1080p";
    aspectRatio: "16:9";
  };
  input: {
    characters: { name: string; imagePath: string }[];
  };
  stages: Record<StageName, {
    status: "pending" | "in_progress" | "completed" | "failed";
    attempts: number;
    startedAt?: string;
    completedAt?: string;
    artifacts: Record<string, string>;  // name → file path
    error?: string;
  }>;
}

type StageName =
  | "screenplay"    // Stage 0
  | "characters"    // Stage 1
  | "storyboard"    // Stage 2
  | "prompts"       // Stage 3
  | "video-gen"     // Stage 4
  | "transitions"   // Stage 5
  | "assembly";     // Stage 6
```

**断点续跑逻辑**：
- 每次 stage 状态变更立即写 `state.json`
- `ai-film resume` 从最后一个未完成的 stage 继续
- `ai-film resume --from storyboard` 强制从指定 stage 重跑
- 已完成的 stage 产出物不删除（除非用户指定 `--clean`）

## 8. CLI 接口

```bash
# 创建新项目
ai-film create \
  --story "一个科学家和机器人在有毒森林中探险" \
  --character scientist:./photos/scientist.png \
  --character robot:./photos/robot.png \
  --duration 60 \
  --style cinematic \
  --seed 42

# 运行流水线（从头或断点续跑）
ai-film run <project-id>

# 从指定阶段重跑
ai-film run <project-id> --from storyboard

# 查看状态
ai-film status <project-id>

# 重新生成某个视频片段
ai-film regen <project-id> --clip 3

# 列出所有项目
ai-film list

# 清理项目中间文件（保留最终视频）
ai-film clean <project-id>
```

## 9. 关键设计决策

| # | 决策 | 选择 | 原因 |
|---|------|------|------|
| 1 | 全火山引擎 vs 混合 | **全火山引擎** | 统一 key、统一代理、用户当前无 OpenAI 额度 |
| 2 | 图片生成方式 | **Seedream 整板生成优先，逐格生成降级** | 整板一次调用更省，逐格更可控 |
| 3 | 视频生成串行 vs 并行 | **首段串行（帧续接），后续可并行** | 首段无前驱帧依赖，用模式B时可并行 |
| 4 | 文件上传 | **需验证代理是否支持** | 视频生成的 image/reference_images 需要 URL |
| 5 | 状态持久化 | **每阶段完成即写入 JSON** | 断点续跑是核心需求 |
| 6 | 技术栈 | **TypeScript + Node.js** | 用户选择；OpenAI SDK 有 TS 版本 |

### 文件上传问题（待验证）

视频生成需要 `image` / `reference_images` 参数传入 URL。需确认：
1. 代理是否支持将本地图片转为 URL？
2. 如果不支持，是否需要自建文件服务或使用火山引擎 OSS？
3. **临时方案**：将图片 base64 编码传入（如果 API 支持）

## 11. 最脆弱的假设

**假设 1**：Seedream 5.0 能生成高质量的多格分镜板。
**如果失败**：退化为逐格生成（12 次 API 调用），增加耗时和成本，但可控性更强。

**假设 2**：代理支持图片/视频文件的 URL 传入方式。
**如果失败**：需要搭建文件托管服务，或在 API 支持 base64 输入时走 base64 通道。

**假设 3**：Seedance 的 `reference_images` 能保持角色一致性（约 70-80% 成功率）。
**如果失败**：退化为 `image`（首帧锚定）模式，牺牲构图自由度换一致性。
