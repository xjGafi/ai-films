# 首帧合成 Stage 技术方案

> 解决 Seedance 2.0 的 image/last_frame_image 与 reference_images 互斥问题，
> 使 pipeline 同时获得角色一致性和帧级衔接能力。

---

## 1. 核心矛盾

Seedance 2.0 有两种互斥的工作模式：

| 模式 | 参数 | 优势 | 劣势 |
|------|------|------|------|
| Mode A | `image` + `last_frame_image` | 帧级精确衔接 | 不能传 `reference_images`，角色漂移 |
| Mode B | `reference_images`（最多 9 张） | 角色一致性好 | 无首帧/尾帧锚定，段间画面跳变 |

当前代码（`3-prompts.ts` 的 `determineVideoGenMode()`）在两者间二选一：连续动作用 Mode A，其余用 Mode B。结果是：

- Mode A 段：衔接好但角色飘
- Mode B 段：角色稳但衔接跳

**两个问题无法同时解决。**

---

## 2. 解决方案

**用 Seedream 图片生成 API 主动合成每段视频的首帧和尾帧图，然后全部作为 `reference_images` 传入，统一走 Mode B。**

核心思路：

1. 根据 shot 描述 + 角色参考图 + 风格设定，用 Seedream 为每段生成一张「首帧图」和一张「尾帧图」
2. 相邻段共享帧图：seg[N] 的尾帧 = seg[N+1] 的首帧
3. 视频生成时，首帧图 + 尾帧图 + 角色参考图 + 分镜 panel 全部放入 `reference_images`
4. prompt 中用 `[Image1]`、`[Image2]` 等明确引用每张图的角色

这样一次 API 调用同时拿到：
- **角色一致性**（角色参考图在 reference_images 中）
- **帧级衔接暗示**（首帧/尾帧图在 reference_images 中 + prompt 引用）

### 精确度评估

`reference_images` 不是硬锚定（不如 Mode A 的 `image` 参数精确），但：
- 比纯文本 CONTINUITY NOTE 可靠得多
- 社区实践（capy-video-gen-skill 300 次实验）验证了 reference_images 的有效性
- `reference_images[0]` 获得最高保真度，首帧图放在第一位

**结论：当前 API 约束下的最优解。**

## 5. 关键设计决策

### 5.1 首帧图尺寸

目标是匹配 Seedance 输出分辨率：
- 720p → 1280×720
- 1080p → 1920×1080

但 Seedream API 有最小像素数限制（≥ 3,686,400 px），1280×720 = 921,600 px 不够。

**方案**：生成 1920×1920（满足最小像素数），再用 sharp resize 到目标 16:9 尺寸。与 storyboard stage 的做法一致。

从 `state.config.resolution` 读取目标分辨率，不硬编码。

### 5.2 衔接链：共享图片策略

```
seg1-first.png  ← 独立生成（第一段首帧）
seg1-last.png   ← 独立生成
seg2-first.png  → 复制自 seg1-last.png
seg2-last.png   ← 独立生成
seg3-first.png  → 复制自 seg2-last.png
seg3-last.png   ← 独立生成
...
segN-last.png   ← 独立生成（最后一段尾帧）
```

用**文件复制**（非 symlink）：
- 跨平台兼容
- 避免断链风险
- 文件大小（单张 PNG ~1-3MB）cost 可忽略

### 5.3 首帧 prompt 构建策略

不是简单截取 shot 描述，而是合成完整的图片生成 prompt：

```
Generate a single cinematic frame for an AI film.

Scene: [shot.scene 描述]
Action: [第一个 shot 的 action，取动作的起始状态]
Characters present: [角色完整物理描述，从 screenplay.characters 取]
Camera: [shot.type] [shot.camera]
Mood/Emotion: [shot.emotion]
Style: [state.config.style 对应的风格关键词]

Composition must match a 16:9 cinematic frame.
Photorealistic, no text, no UI elements, no borders.
```

尾帧同理，但取 segment 最后一个 shot 的 action **终止状态**。

### 5.4 第一段首帧的特殊处理

第一段没有「前一段的尾帧」可复用，首帧完全独立生成。

prompt 额外加入 storyboard 第一个 panel 的描述作为构图参考，确保与分镜板视觉一致。

### 5.5 reference_images 槽位分配

Seedance 最多 9 张 reference_images。预算分配：

| 槽位 | 内容 | 理由 |
|------|------|------|
| `[0]` | 首帧图 | 第一张获得最高保真度 |
| `[1]` | 尾帧图 | 引导视频走向 |
| `[2..N]` | 角色参考图（每角色 1 张） | 角色一致性 |
| `[N+1]` | 分镜 panel（可选） | 构图辅助 |

上限 9 张。如果角色 > 5 个（极端情况），省略分镜 panel 并在 prompt 中用文字补偿构图信息。

### 5.6 API 调用量估算

每个 segment 需要的 Seedream 调用：
- 首帧图：1 次（第一段）或 0 次（后续段复用前段尾帧）
- 尾帧图：1 次

总调用 = segments 数量 + 1（第一段额外的首帧）

| 视频总时长 | segments 数量 | Seedream 调用次数 |
|-----------|--------------|-----------------|
| 60s | 4 | 5 |
| 90s | 6 | 7 |
| 120s | 8 | 9 |

每次调用约 5-15 秒，总耗时约 30-120 秒，可接受。

## 6. 对 prompts stage 的改动

### 6.1 `determineVideoGenMode()` 简化

移除 Mode A/B 分支判断，统一返回 Mode B：

```typescript
// 改动前：根据 actionContinuous 在 Mode A/B 间切换
// 改动后：统一 Mode B，组装新的 reference_images 列表

function determineVideoGenMode(
  segment, segIdx, segments, charRefMap, screenplay, projectDir, framesDir
): { mode: "modeB"; referenceImageRefs: string[] } {
  const refs: string[] = [];

  // [0] 首帧图（最高保真位）
  const firstFramePath = path.join(framesDir, `segment-${segIdx + 1}-first.png`);
  if (fs.existsSync(firstFramePath)) refs.push(firstFramePath);

  // [1] 尾帧图
  const lastFramePath = path.join(framesDir, `segment-${segIdx + 1}-last.png`);
  if (fs.existsSync(lastFramePath)) refs.push(lastFramePath);

  // [2..N] 角色参考图
  for (const char of screenplay.characters) {
    const refPath = charRefMap.get(char.name);
    if (refPath) refs.push(refPath);
  }

  // [N+1] 分镜 panel（可选，不超过 9 张上限）
  if (refs.length < 9) {
    // 找到对应的 storyboard panel
    const panelPath = findStoryboardPanel(segment, projectDir);
    if (panelPath) refs.push(panelPath);
  }

  return { mode: "modeB", referenceImageRefs: refs };
}
```

### 6.2 prompt 中的图片引用

`buildReferenceDescription()` 需要更新，生成如下格式：

```
[Image1] is the target starting frame — the video should begin from this visual state.

```

## 8. 最脆弱的假设与退化方案

### 假设

**"Seedream 生成的首帧图作为 `reference_images[0]` 传入 Seedance 时，能有效引导视频起始画面的构图和内容。"**

### 如果假设失败

退化方案：对连续动作段改回 Mode A（`image` 参数硬锚定首帧），对非连续段保持 Mode B + 合成帧。

这意味着：
- `4-prompts.ts` 中保留 Mode A/B 分支逻辑
- 首帧合成 stage 的产出仍然有用——Mode A 直接用 `frames/segment-{N}-first.png` 作为 `image` 参数
- **工作量不会浪费**，只是消费方式从 reference_images 变回 image

### 验证策略

实施后先用一个 2-segment 项目测试：
1. 生成首帧/尾帧图 → 目视检查质量
2. 用 reference_images 模式生成视频 → 检查首帧是否被有效引导
3. 对比两段视频的衔接处 → 评估跳变程度
